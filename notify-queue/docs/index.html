notify-queue

快速启动

# 起 Redis + API(:3000) + Worker
docker compose up --build

# 入队通知
curl -X POST http://localhost:3000/api/notifications \
  -H 'content-type: application/json' \
  -d '{"channel":"email","to":"a@example.com","subject":"Hi","body":"Hello"}'

# 任务状态 / 队列统计 / 死信列表 / 死信重投
curl http://localhost:3000/api/notifications/<JOB_ID>
curl http://localhost:3000/api/notifications
curl http://localhost:3000/api/dead-letters
curl -X POST http://localhost:3000/api/dead-letters/<DLQ_ID>/retry

# 跑集成测试（Redis + Jest）
docker compose -f docker-compose.test.yml up --abort-on-container-exit --exit-code-from test

重试与死信配置

自动重试backoff: { type: 'exponential', delay: 500 } → 500ms、1s、2s、4s…（上限 30s）
最大次数MAX_ATTEMPTS（默认 3，env 可调）。耗尽后 BullMQ 标记 failed 并保留记录
死信双保险① 主队列 failed set；② Worker failed 事件把耗尽任务复制进独立队列 notifications-dlq，API 可列表 / 重投
失败注入（测试用）failTimes: N 前 N 次失败后成功（验证重试）；alwaysFail: true 永远失败（验证死信）

集成测试覆盖（Jest）

① 正常消费email / inapp 任务入队 → Worker 消费 → state=completed、投递日志记录；API 入队 201、非法 payload 400 信封
② 失败重试failTimes=MAX_ATTEMPTS-1 → 前几次失败、指数退避重试 → 最终成功，attemptsMade≥N；校验 opts.attempts/backoff
③ 进入死信alwaysFail 耗尽次数 → state=failed + failedReason → 出现在 /api/dead-letters → 复制进 notifications-dlq → deadLettered=true → 重投后成功
队列统计GET /api/notifications 返回 counts 与 maxAttempts

  app.js              # Express 管理 API（可注入 queue/dlq 便于测试）
  server.js           # 启动入口（零依赖 .env 读取）
