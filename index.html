task-optimistic-lock

任务更新的乐观锁 / 版本号实现：更新必须携带读到的 version，服务端原子 CAS 比对——并发冲突返回 409 Conflict，前端弹出「任务已被他人修改，请刷新」并提供一键刷新。附并发测试（两个请求同时改同一任务 → 一 200 一 409）。

version 字段乐观锁 原子 CAS UPDATE 409 CONFLICT 前端刷新提示 并发集成测试 docker compose up

冲突检测流程

读任务
拿到 version=3
→
PUT 带 version:3
→
UPDATE ... WHERE id=? AND version=3
→
changes=1
✅ 200 · version→4
changes=0
❌ 409 CONFLICT
并发写者先改了行
version 已变 4
→
409 + details:
expectedVersion / currentVersion / task
→
前端 toast
「任务已被他人修改」
→
⟳ 刷新拿 v4
再提交

409 响应信封

HTTP/1.1 409 Conflict
{
  "error": {
    "code": "CONFLICT",
    "message": "Version conflict: this task was modified by another request. Refresh to get the latest version.",
    "details": {
      "expectedVersion": 3,
      "currentVersion": 4,
      "task": { "id": "t-...", "title": "最新的标题", "version": 4 }
    }
  }
}

校验失败（缺 version / 非法字段）→ 400 BAD_REQUEST；未知任务 → 404 NOT_FOUND。全部统一信封 {error:{code,message,details?}}。

快速启动

# 起 API + 看板（SQLite 持久化 + 种子）
docker compose up --build
# 看板 UI:  http://localhost:3000/
# API 索引: http://localhost:3000/api

# 跑并发测试（两条验收）
npm install && npm test
# 或
docker compose --profile test run --rm test

# 手动验证 409
curl -X PUT http://localhost:3000/api/tasks/t-1 \
  -H 'content-type: application/json' -d '{"version":1,"title":"A"}'   # 200
curl -X PUT http://localhost:3000/api/tasks/t-1 \
  -H 'content-type: application/json' -d '{"version":1,"title":"B"}'   # 409

API

方法路径说明
GET/api/tasks列表（page pageSize q），每项含 version
GET/api/tasks/:id详情（含 version）
POST/api/tasks创建 {title, description?, status?}，version=1
PUT/api/tasks/:id必须带 version；不匹配 → 409；缺省 → 400；成功 → version+1
DELETE/api/tasks/:id?version=N带版本守卫删除；不匹配 → 409；204 成功
GET/health · /api健康检查 · 端点索引

并发测试覆盖（Jest + Supertest）

① 两个请求同时改同一任务Promise.all 发两个携带相同 version 的 PUT → 断言状态码集合恰为 {200, 409}；赢家 version+1；输家信封含 expectedVersion/currentVersion；最终 DB version 只 +1、title 为赢家写入值
② 5 写者踩踏5 个同 version 请求并发 → 恰好 1 个 200、4 个 409、version 只 +1（CAS 只允许单个胜者）
③ 正常路径正确 version → 200 且 version+1；过期 version → 409 且 details.currentVersion 正确；缺 version → 400；未知 id → 404
④ 带版本删除过期 ?version → 409；正确 → 204 后 GET 404

前端（看板 UI）

409 提示更新失败弹 toast「⚠️ 409 版本冲突 · 任务已被他人修改（当前版本 vN），请刷新获取最新版本后再改」，按钮 ⟳ 刷新并重试 / 仅刷新
⚡ 模拟并发冲突一键对同一任务同时发两个相同 version 的 PUT，直观展示 200 / 409 与刷新提示
乐观并发操作编辑标题 / 推进状态 / 带版本删除，全部回传读到的 version，冲突时统一走刷新流程
零依赖单文件public/index.html（原生 fetch + CSS，无框架、无需构建）
